# Manufacturing AI Weekly Intelligence

面向智能制造 AI 解决方案架构师的周度行业情报报告框架。

项目将公开新闻、行业报告、厂商产品发布和前沿方案统一映射到 **Manufacturing AI Map**，帮助读者快速理解：

- 制造业 AI 正在发生什么变化；
- 哪些技术方向正在形成行业共识；
- 哪些能力已经产品化；
- 哪些端到端方案值得进入解决方案储备；
- 当前信息集中在哪些制造环节，哪些区域仍存在知识盲区。

当前版本是一个 **纯静态前端项目**，无构建工具、无后端、无外部运行时依赖。核心目标是让每周更新尽量只修改数据文件。

## 当前界面与周更能力（2026-08-14）

- 桌面端采用横向情报工作台：左侧 Manufacturing AI Map、中部情报流、右侧本周信号；平板与手机自动重排。
- `WEEKLY_SIGNALS`、报告元信息和情报条目均在 `data.js` 维护。
- 成熟度通过稳定枚举参与筛选和统计，并兼容现有中文历史值。
- 支持清除筛选、结果计数、最新/影响/前沿度排序，以及 URL 保留当前视图。
- 页面启动时校验重复 ID、知识库、制造环节、评分、必填字段、URL 和成熟度映射。
- 数据或应用初始化失败时，页面向读者显示明确提示。
- 首页情报卡直接展示“发生了什么”和“核心判断”，并通过两行限制控制阅读密度；点击后打开二级知识卡片。
- 二级卡片以动态 SWOT 解读为主体，知识元数据、Manufacturing AI Map、能力标签和原始来源作为辅助信息展示。
- 影响程度通过首页卡片顶部色带表达：低影响为中性色，高影响逐步过渡到红色信号色。

## 1. 页面结构

页面面向最终读者，仅保留三个主要阅读模块：

1. **趋势总览**
   - 高价值情报条目数
   - 平均业务影响评分
   - 高前沿度条目数
   - 已进入产品 / 采用 / 规模化阶段的条目数
   - Manufacturing AI Map 覆盖热度
   - 本期核心信号

2. **Manufacturing AI Map**
   - 按制造业务环节展示本期情报覆盖情况；
   - 点击任一业务环节后，自动跳转到情报区并筛选相关卡片。

3. **新闻 / 报告情报卡片**
   - 支持四个知识库切换；
   - 支持关键词搜索；
   - 支持制造环节、来源机构、成熟度筛选；
   - 每张卡片展示“发生了什么、为什么重要、与 AI Map 的关系、AI 能力标签、成熟度和原始来源”。

---

## 2. 四个知识库

所有情报必须归入以下四类之一：

| 知识库 | 解决的问题 |
|---|---|
| 行业趋势 | 制造业整体正在发生什么变化？ |
| 技术趋势 | 制造业 AI 技术栈正在向哪里演进？ |
| 新兴产品 | 哪些 AI 能力已经被厂商产品化？ |
| 前沿方案 | 哪些端到端方案可能改变制造业务或系统架构？ |

`LIBRARIES` 定义在 `data.js` 中。

---

## 3. Manufacturing AI Map

当前 Map 包含 10 个制造业务环节：

1. 产品研发
2. 工艺工程
3. 生产计划
4. 生产执行
5. 质量
6. 设备维护
7. 供应链/物流
8. 工厂工程
9. 现场作业
10. 机器人/自动化

Map 不单独维护统计数据。

每条情报通过 `maps` 字段声明与哪些业务环节相关，`app.js` 会自动计算：

- 每个环节对应的情报数量；
- 覆盖热度；
- Map 卡片中的数量；
- 点击 Map 后的联动筛选。

因此，每周新增情报时，正确填写 `maps` 是数据维护的关键步骤。

## 4. 项目文件结构

```text
manufacturing_ai_weekly_framework/
├── index.html      # 页面骨架和固定文案
├── styles.css      # 全部页面样式
├── app.js          # 渲染、计算、搜索、筛选与交互逻辑
├── data.js         # 周度情报数据；运营更新的核心文件
├── README.md       # 使用与维护说明
└── HANDOVER.md     # 给后续开发者 / Codex 的技术交接说明
```

### 文件职责

#### `index.html`

负责 DOM 结构和页面模块。

正常周度更新不应修改本文件。

当前仍有一处例外：**“本期四个最强信号”仍为静态 HTML 文案**。该问题已记录在 `HANDOVER.md` 的 P0 Backlog 中。

#### `styles.css`

负责：

- 页面视觉风格；
- 响应式布局；
- 指标卡、热度条、AI Map、情报卡片；
- 搜索区和筛选器；
- Hover / Active 状态。

#### `app.js`

负责：

- 根据 `data.js` 计算页面指标；
- 计算 AI Map 覆盖度；
- 渲染 AI Map；
- 渲染情报卡片；
- 动态生成筛选选项；
- 搜索；
- 知识库切换；
- Map → 情报卡片联动。

#### `data.js`

周度运营核心文件，包含：

- `REPORT_META`
- `MANUFACTURING_STAGES`
- `LIBRARIES`
- `INTELLIGENCE_DATA`

## 5. 本地运行

### 最简单方式

将项目完整下载到同一目录后，直接打开：

```text
index.html
```

页面通过相对路径加载：

```html
<link rel="stylesheet" href="styles.css" />
<script src="data.js"></script>
<script src="app.js"></script>
```

因此四个前端文件必须保持在同一目录，除非同步修改引用路径。

### 推荐开发方式

为了避免浏览器对本地文件的限制，也可以启动任意静态 Web Server，例如：

```bash
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000
```

项目当前没有 npm 依赖，也不需要执行 build。

## 6. 每周更新流程

原则：**优先只修改 `data.js`。**

### Step 1：更新本期元信息

```javascript
const REPORT_META = {
  date: "2026-08-14",
  issue: "2026-W33",
  headline: "Agentic Manufacturing × Digital Twin × Physical AI"
};
```

- `date`：报告基线日期；
- `issue`：周度编号，目前预留；
- `headline`：页面 Hero 区域的本期观察主线。

### Step 2：新增本周情报

在 `INTELLIGENCE_DATA` 中新增对象。

推荐模板：

```javascript
{
  id: "S05",
  lib: "前沿方案",
  title: "方案标题",
  date: "2026-08-20",
  org: "厂商 / 机构",
  summary: "一句话说明发生了什么。",
  signal: "一句话说明为什么值得解决方案架构师关注。",
  maps: ["生产执行", "质量"],
  caps: ["Industrial Agent", "Digital Twin"],
  url: "https://...",
  maturity: "试点",
  impact: 5,
  novelty: 4
}
```

### Step 3：刷新页面

页面会自动重新计算：

- 总情报数；
- 平均 Impact；
- Novelty = 5 的高前沿度条目数；
- 产品 / 采用 / 规模化阶段条目数；
- Manufacturing AI Map 覆盖热度；
- 各知识库数量；
- 来源机构筛选项；
- 成熟度筛选项；
- 制造环节筛选项。

### Step 4：人工检查本期结论

当前仍需人工确认：

- 本期 `headline`；
- 首页四个核心信号；
- 卡片 `signal` 是否真正表达了“为什么重要”；
- `maps` 是否准确；
- `impact` / `novelty` 是否符合统一评分标准。

## 7. 数据字段说明

| 字段 | 类型 | 必填 | 用途 |
|---|---|---:|---|
| `id` | string | 是 | 情报唯一 ID |
| `lib` | string | 是 | 四个知识库之一 |
| `title` | string | 是 | 新闻 / 报告 / 产品 / 方案标题 |
| `date` | string | 是 | 发布日期，建议 `YYYY-MM-DD` |
| `org` | string | 是 | 来源机构 / 厂商 |
| `summary` | string | 是 | “发生了什么”的一句话摘要 |
| `signal` | string | 是 | “为什么重要”的核心分析 |
| `maps` | string[] | 是 | 对应 Manufacturing AI Map 环节 |
| `caps` | string[] | 是 | AI / Industrial Capability 标签 |
| `url` | string | 是 | 原始来源 URL |
| `maturity` | string | 是 | 当前成熟度 |
| `impact` | number | 是 | 业务 / 行业影响评分，1–5 |
| `novelty` | number | 是 | 技术 / 架构前沿度，1–5 |

## 8. 内容编写口径

### `summary`

目标：让读者在 5–10 秒内知道发生了什么。

建议包含：

- 谁；
- 发布 / 推出了什么；
- 作用于哪个制造问题或流程。

避免：

- 直接复制新闻标题；
- 大段厂商营销文案；
- 无法形成业务理解的技术名词堆砌。

### `signal`

目标：回答 **“所以呢？这为什么值得 AI 解决方案架构师关注？”**

优先分析：

- 是否改变制造 AI 技术架构；
- 是否出现新的可复用解决方案模式；
- 是否从 Demo 进入 Pilot / Production / Scale；
- 是否出现明确制造 KPI；
- 是否打通 MES / PLM / SCADA / PLC / Robot 等工业系统；
- 是否改变 Agent、Digital Twin、Physical AI 的角色。

## 9. 数据评分建议

### Impact

| 分数 | 判断参考 |
|---|---|
| 1 | 局部功能更新，对制造业务影响小 |
| 2 | 有一定产品价值，但影响范围有限 |
| 3 | 对某一制造业务场景有明显价值 |
| 4 | 可能影响多个业务环节或形成新的产品模式 |
| 5 | 可能改变行业方向、制造架构或产生大规模业务价值 |

### Novelty

| 分数 | 判断参考 |
|---|---|
| 1 | 已成熟多年的常规能力 |
| 2 | 既有能力的小幅升级 |
| 3 | 新产品化 / 新组合方式 |
| 4 | 明显的新架构或新场景 |
| 5 | 前沿技术进入工业现场，或出现新的工业 AI 范式 |

## 10. 当前产品原则

后续开发应尽量维持以下原则：

1. **读者优先**：页面首先帮助人快速理解行业变化，不展示内部研究流程。
2. **AI Map 是主索引**：任何新情报都必须能够解释与制造业务环节的关系。
3. **四库是内容分类，Map 是业务分类**：两者不应混在一个维度里。
4. **卡片先给结论**：读者应先看到核心分析，再决定是否打开原文。
5. **数据驱动**：周度更新尽量只新增数据，不修改页面代码。
6. **原始来源可追溯**：每张卡片保留原始 URL。
7. **尽量使用一手来源**：WEF、厂商官方、正式研究报告、权威媒体优先。
